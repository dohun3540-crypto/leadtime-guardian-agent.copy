# 데이터 구성

## 데이터 소스
- 참고 공개 데이터: 배송일·예정일 등 시계열 지연 패턴을 분석하는 데 사용 가능.
- 필수 문서 실습: 발주서, 납기 변경 통보서, 견적서 PDF 또는 이메일 본문.
- 재고/고객 주문/대체 공급업체 테이블: 합성 CSV를 사용해 실제 업무 시나리오 재현.
- 공개 배송 데이터의 배송 지연과 공급업체의 제조·구매 납기 지연은 동등하지 않다. 모델 성능을 혼동해 주장하지 않는다.

## 목표
- 문서 20건 이상(권장 24~30건).
- 모든 문서에 문서 ID, 종류, 케이스 유형, 정답 JSON.
- Studio 추출 JSON 필드명과 정답 JSON 필드명이 일치하도록 관리.
- 난이도 다양화: 정상 납기/지연/부분 입고/날짜 누락/수량 변경/다중 품목/정보 충돌/스캔 품질 저하.
- 예: case_id, doc_id, po_id, product_id, original_delivery, revised_delivery, quantity, supplier, currency, unit_price.
- 날짜 YYYY-MM-DD; 수량 정수; 통화 명시; 결측은 null.

## 품질 검증
- 케이스 유형별 정확도, 필드별 일치율, 처리 실패율, 검토 필요 케이스 탐지율 측정.
- 숫자 계산은 Python 단위 테스트로 검증.
- 합성 문서에는 가상 자료임을 명시.
- 민감 원본·API 키는 저장소에 포함하지 않음.
