[8차 GitHub의 정확한 변경점]
1. NormalizeDocuments와 IndependentQA 실제 입력 비교는 JSON 타입을 구분합니다. Boolean false가 숫자 0으로 바뀌거나 반대로 바뀐 경우 무조건 동일 판정하지 않습니다.
2. --stage-intake-manifest 검사에서 잘못된 원본 SHA, 운영 Job, C001 Case 또는 Normalize 문서 값 충돌이 발생하면 Python V6 계산 **전에** FAIL과 NOT_RUN으로 종료합니다. 단순 누락/미확보 Stage는 BLOCKED로 유지합니다.
3. 동일 (Job ID, Step Run ID)가 다른 Step에서 중복되거나, 허용되지 않은 Extract 분기·Stage 타입, QA Input와 Report가 서로 다른 QA Sandbox Job에 속하면 FAIL합니다. 운영 Job과 QA Sandbox Job이 서로 다를 수 있다는 기존 원칙은 유지합니다.
4. B0/E1 Normalize 원본 로컬 JSON을 비교할 때 파일 원본 SHA가 해당 비교 manifest의 NormalizeDocuments step_artifacts.original_sha256과 실제로 일치해야 비교합니다. 같은 파일명이나 두 PDF의 자기신고 SHA만으로 E1의 공정성/정확도를 인증하지 않습니다.
5. Stage JSON 입력은 파일당 32 MiB, manifest 1 MiB로 제한하고 외부 폴더로 이어지는 상대 경로·심볼릭 링크 및 비정상 중첩 JSON은 실패 처리합니다. 실제 원본 JSON이 이보다 큰 경우 원본 바이트를 수정하지 말고 크기와 설명을 함께 알려주세요.
